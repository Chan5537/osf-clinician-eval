# OSF — Clinician Evaluation Interface

A single-page app for the OSF clinician evaluation (UCLA Health Intelligence Lab). A clinician
reviews each case — patient context, a clinical query, and **source-blinded** responses (A / B / C) —
and rates every response on four 1–5 Likert scales (Context · Justifiability · Personalization ·
Harm). Scoring happens in the **focus view** — one response at a time, its rubric alongside, both
panes scrolling independently — with a **read-only compare view** (all responses side by side, no
scoring controls) one click away. Frontend-only: no backend, progress saved in the browser,
results exported as JSON/CSV.

**Live:** https://chan5537.github.io/osf-clinician-eval/

## Stack

React 19 · Vite · TypeScript · Tailwind CSS v4 · shadcn/ui · react-markdown. State is a single
`useReducer`; no router, no network.

## Develop

```bash
npm install
npm run dev      # http://localhost:5173/osf-clinician-eval/
npm run build    # type-check + production build to dist/
```

## How it works

- **Data** — cases live in `src/data/demo-cases.generated.json`, generated by the Python exporter
  (`osf-human-eval/scripts/export_calibrated_batch_to_ui.py`). The arm identity is a hidden
  un-blinding key, never rendered. (The file still carries per-response boolean `atoms` from the
  retired hybrid rubric — ignored since schema v6.)
- **Rubric** — the 4 Likert scales defined verbatim in `src/lib/rubric-config.ts`, rendered by
  `src/components/LikertRubric.tsx` inside `FocusReview.tsx` (one arm at a time, response left /
  rubric right, per-arm tabs). The compare view is read-only (`ResponsePair` only) until a true
  A-vs-B comparison rubric exists.
- **State** — `src/lib/{session,reducer,storage}.ts`: multi-case session, Likert-scoring reducer,
  versioned localStorage. Bump `SCHEMA_VERSION` in `session.ts` if case content/shape changes.
- **Export** — `src/lib/export.ts`: long-format JSON/CSV (one row per case × response × Likert
  dimension, with the un-blinding `arm` column), offered only on the completion screen.

## Blinding — do not regress

The UI must never reveal which response is which arm. The blinding-critical surface is the **response
content** a clinician reads (each arm's `markdown`) — it must contain none of: `Agent, Base, GPT,
Gemini, OSF, tool, ReAct, oracle, SleepFM, "ground truth"`. Gate on the response content, not the whole
bundle (the bundle legitimately contains the `react` library name, the `/osf-clinician-eval/` base path,
the data field `futureDiseaseGroundTruth`, and the verbatim SensorFM rubric anchor "…ground truth
signals" — none of which identify an arm):

```bash
# response-content gate — the surface that actually blinds. Expect 0.
python3 - <<'PY'
import json, re
cases = json.load(open("src/data/demo-cases.generated.json"))
pat = re.compile(r'\b(Agent|Base|GPT|Gemini|OSF|tool|ReAct|oracle|ground.?truth|SleepFM)\b', re.I)
leaks = [(c["case_id"], r["label"], pat.findall(r.get("markdown","")))
         for c in cases for r in c["responses"] if pat.search(r.get("markdown",""))]
print("response-content leaks:", len(leaks))
assert not leaks, leaks
PY
```

## Deploy (GitHub Pages)

CI builds and publishes on push to `main` (`.github/workflows/deploy.yml`). The site is served under
`/<repo>/`, so `VITE_BASE` **must** equal `/osf-clinician-eval/` (set in the workflow and as the Vite
default). A white page after deploy = `VITE_BASE` ≠ the repo name. Never hardcode a leading-slash asset
path in TSX — use an ESM import or `import.meta.env.BASE_URL`.
