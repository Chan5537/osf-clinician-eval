# OSF — Clinician Evaluation Interface

A single-page app for the OSF clinician evaluation (UCLA Health Intelligence Lab). A clinician
reviews each case — patient context, a clinical query, and **source-blinded** responses (A / B / C) —
and scores every response on a per-response weighted-boolean checklist (Yes / No / N/A). Frontend-only:
no backend, progress saved in the browser, results exported as JSON/CSV.

**Live:** https://chan5537.github.io/osf-clinician-eval/

## Stack

React 19 · Vite · TypeScript · Tailwind CSS v4 · shadcn/ui · react-markdown. State is a single
`useReducer`; no router, no network.

## Develop

```bash
npm install
npm run dev      # http://localhost:5173/osf-clinician-eval/
npm run build    # type-check + production build to dist/
```

## How it works

- **Data** — cases live in `src/data/demo-cases.generated.json`, generated by the Python exporter
  (`osf-human-eval/scripts/export_calibrated_batch_to_ui.py`). Each response carries its own
  weighted-boolean atoms; the arm identity is a hidden un-blinding key, never rendered.
- **Rubric** — `src/components/ChecklistRubric.tsx`: per-response Yes/No/N/A atoms grouped by category
  (Future-disease risk · Sleep-data interpretation · Safety).
- **State** — `src/lib/{session,reducer,storage}.ts`: multi-case session, atom-scoring reducer,
  versioned localStorage. Bump `SCHEMA_VERSION` in `session.ts` if case content/shape changes.
- **Export** — `src/lib/export.ts`: long-format JSON/CSV (one row per case × response × atom, with the
  un-blinding `arm` column), offered only on the completion screen.

## Blinding — do not regress

The UI must never reveal which response is which arm. Response content must contain none of:
`Agent, Base, GPT, Gemini, OSF, tool, ReAct, oracle, "ground truth"`. The shipped bundle is the gate:

```bash
npm run build
grep -roiE '\b(GPT|Gemini|OSF|ReAct|oracle|ground.?truth)\b' dist/assets/   # expect 0
```

## Deploy (GitHub Pages)

CI builds and publishes on push to `main` (`.github/workflows/deploy.yml`). The site is served under
`/<repo>/`, so `VITE_BASE` **must** equal `/osf-clinician-eval/` (set in the workflow and as the Vite
default). A white page after deploy = `VITE_BASE` ≠ the repo name. Never hardcode a leading-slash asset
path in TSX — use an ESM import or `import.meta.env.BASE_URL`.
